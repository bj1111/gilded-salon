# Gilded Salon Bonus Buy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three purchasable options — Buy Free Spins (`bonus`), Buy Super Free Spins (`super`, 2 chips locked before the first spin) and Bonus Hunt (`hunt`, 3x per spin, free spins ~1 in 50) — with simulated math at 96.50% RTP and a Gilded Salon buy menu.

**Architecture:** Three new math modes are simulated and weighted next to the untouched `base` books (natural weighting, one free parameter per mode solved for exact RTP). The web app builds SDK bet-mode metadata from the exported config, drives `stateBet.activeBetModeKey` from its own Pixi buy menu, and reuses the existing free-spin presentation; the only new math event use is `newStickyWilds` before the first free spin.

**Tech Stack:** Python math-sdk (venv `math-sdk/env`, run from `math-sdk/` with `env/bin/python`), SvelteKit 2 + Svelte 5 + PixiJS 8 via pixi-svelte, vitest 3.2.4, playwright-core e2e with `tools/mock-rgs.mjs`.

**Spec:** `stake /docs/superpowers/specs/2026-10-08-bonus-buy-design.md`

## Global Constraints

- RTP 0.965 and max win 10000x in every mode; `base` books and lookup table stay byte-identical (hashes in `backups/math-hashes.txt`).
- Mode keys exactly `bonus`, `super`, `hunt`; SDK types `buy`, `buy`, `activate`. Hunt cost exactly 3.
- Buy prices are whole numbers solved from simulation (`round(V / 0.965)`); no price is hard-coded in the web app — it reads `config.betModes[mode].cost`.
- Published trigger rates must equal the reels' natural rates (readme rule against engineered near-misses); buy-mode trigger mix within ±10% of natural.
- No external network hosts in the build; no git commits unless the user asks (the repo is not under git — skip every commit step).
- Social mode: no string from `copy(true)` may contain a restricted phrase (`copy.test.ts` scans all of them).
- Buy UI hidden when `stateConfig.jurisdiction.disabledBuyFeature` or in replay.
- Every buy needs a confirm step; Bonus Hunt TURN ON does not.
- Touch targets ≥ 44 px on phones; layout tests in `src/ui/layout.test.ts` must keep passing.

## Review Focus

1. **Holding Space or autoplay right after a buy** must not buy again. Expect the next round to be `mode=base` (or `hunt` if it was on). Test: e2e `h` holds Space for 3 rounds after a buy and asserts every `/wallet/play` after the first carries `mode` base. Owned by Task 8.
2. **Changing the bet inside the menu so the price exceeds the balance** must dim the card at once, and CONFIRM must not send a play. Test: `buyRules.test.ts` `canAfford` boundary (`bet*cost == balance` is affordable, `+0.01` is not), plus e2e `k`. Owned by Tasks 5 and 8.
3. **Reloading mid-way through a bought Super round** (after the 2 opening chips) must restore both chips and the counter, and must not drop them again. Test: integrity-style unit test on `createBonusSnapshot` with a `super` book cut after `newStickyWilds`, plus e2e `i`. Owned by Task 9.
4. **Turning Hunt on, then lowering the balance below 3x the bet**: spin must be disabled the same way as a base spin the player can't afford (SDK `isBetCostAvailable` already multiplies for `activate`). Test: e2e `j` sets the balance via the admin API and asserts no play is sent. Owned by Task 11.
5. **Replay of a `super` or `hunt` round** must play from the URL `mode` without wallet calls, with the buy button hidden. Test: e2e `f2`. Owned by Task 11.
